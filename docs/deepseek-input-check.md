## 修正

- 保留严格 UTF-8 解码的原文，包括所有空格、换行和控制字符，不修剪、不替换。
- 正常词元只附顺序标签，不再附 HEX、字节数、等级与 ID；提示词聚焦词义、意象和生活行动。
- 无法独立解码的片段仍单独提供必要字节说明，不虚构 Unicode 文本。
- API 外层 JSON 仍按协议编码；不再将原文额外序列化成内层 JSON 字符串。
- 提示词版本更新为 reading-v3；已保存的释读保留原版本，新抽签或尚未生成的签单使用新版本。

## 能确认与不能确认的事项

已检查真实请求中的原文内容块：第一组的第一个内容块是 `" lord"`，第一字节仍为 0x20。独立测试还覆盖了全部 128,815 个词元的无损字节还原。

[官方 Chat Completions 接口](https://api-docs.deepseek.com/api/create-chat-completion/) 接收文本消息，而不是指定来源词表的 input IDs。因此保留原文不意味着强制使用某个内部 token；text 内容块也不是内部 token 边界。即使空格与单词被编码为一个内部 token，模型仍可能在释读时讨论其中的空格。
